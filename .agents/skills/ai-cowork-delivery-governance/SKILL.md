# AI Cowork Delivery Governance

This skill turns the v3.6 flow into consistent dashboard, presentation, SOP, and proposal content. The core idea is not "AI replaces delivery roles"; it is "Claude Cowork speeds up PM/QA整理、起草、比對、提醒, Claude Code speeds up engineering開發、測試、文件, and humans keep scope, quality, technical, and delivery responsibility."

## Workflow

1. Identify the target artifact: dashboard, presentation, SOP, proposal, diagram, or review.
2. Read the relevant reference before writing: use the table below.
3. Keep the three-stage structure: 開發前, 開發中, 開發後.
4. Preserve role boundaries: PM, QA, 工程師 are responsible; Cowork and Claude Code are assistants.
5. Preserve the key gates: SOW / 報價 / 交期, Change Request, UAT, 正式簽收 / 上線同意.
6. For dashboard/SOP content, include fuller tables and explanations.
7. For presentation content, use short slide-ready wording and put the full architecture image before the three detail images.
8. For diagram review, check whether the diagram matches v3.6 ordering and whether it is too dense for projection.
9. Validate output against the checklist in `references/v3.6-process.md`.
