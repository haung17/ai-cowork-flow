# Presentation Guide

Use four visual flow slides:

1. Full architecture
   - Purpose: show the complete governance flow.
   - Talk track: this is a three-stage delivery flow for freelance software projects, with PM, QA, engineer, Claude Cowork, and Claude Code intervention points.

2. Pre-development detail
   - Focus: requirements, QA/engineering evaluation, SOW / pricing, customer confirmation, scheduling.
   - Talk track: do not rush pricing; evaluate test and technical cost before SOW / pricing confirmation.

3. Mid-development detail
   - Focus: PR, CI, Code Review, QA, issue classification, Change Request.
   - Talk track: bugs, unclear specs, and new requirements must be routed differently so scope change is not treated as free bug fixing.

4. Post-development detail
   - Focus: version freeze, UAT environment, Smoke Test, UAT, production deployment, documents, warranty handoff.
   - Talk track: post-development is not direct deployment; freeze the version, deploy UAT, run internal Smoke Test, then let the customer accept.

Slide wording rules:
- Keep text short enough to read while the image is on screen.
- Use full architecture as overview only.
- Do not add more nodes to the architecture slide.
- Use the dashboard or SOP for full detailed wording.
