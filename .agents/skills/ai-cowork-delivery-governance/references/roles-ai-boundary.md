# 角色責任與 AI 邊界

## 核心定位

AI 工具是加速助手，不是責任主體。所有範圍、品質、技術與交付責任，由 PM、QA、工程師人工承擔。

---

## PM

### 主要人工責任（不可委外給 AI）

- 需求訪談與客戶溝通
- 範圍切分與功能優先序決策
- SOW / 報價 / 交期確認（客戶 Gate 主導）
- 排程與里程碑管理
- Change Request 協調與客戶簽核
- 結案與保固交接

### Cowork 可輔助

- 會議紀錄整理 → User Story / 需求清單初稿
- SOW / 報價項目初稿
- Sprint Demo 腳本草稿
- Release Note 初稿
- 結案摘要初稿
- 問題影響分析整理

**責任邊界**：AI 可幫 PM 整理和起草，但不能替 PM 承諾報價、範圍、交期、簽核任何客戶文件。

---

## QA

### 主要人工責任（不可委外給 AI）

- 測試策略制定（手測 vs 自動化比例）
- 高風險功能識別與測試優先序
- 測試執行（功能測試、探索測試、回歸測試）
- 缺陷嚴重等級判斷
- 驗收條件確認（符合 SOW 要求）
- Smoke Test 執行（UAT 前後）
- 上線後監控與確認

### Cowork 可輔助

- 測試案例初稿（正常 / 異常 / 邊界 / 權限）
- 測試資料需求整理
- Bug 描述整理 / 重現步驟格式化
- 測試報告初稿
- 問題分類建議

**責任邊界**：AI 可幫 QA 產生測試草稿和整理文件，但不能取代 QA 對品質風險、驗收結果的判斷，也不能自動決定「通過 / 不通過」。

---

## 工程師

### 主要人工責任（不可委外給 AI）

- 技術可行性評估與工時估算
- 架構決策
- Code Review 與合併決策
- 部署決策（何時部署、是否回滾）
- 安全性審查

### Claude Code 可輔助

- 功能實作
- 單元測試產生
- Bug 修正
- PR 描述初稿
- API 文件 / 技術文件生成
- DB Schema 草稿
- CLAUDE.md 初始化
- Migration / Release script 草稿

**責任邊界**：Claude Code 可產生程式碼和文件，但工程師必須 Review、測試、確認。Claude Code 不應直接執行 Production 部署或做架構決策。

---

## 三層 AI 策略

| 層級 | 定義 | 適合範例 |
|---|---|---|
| **第一層：全自動** | 規則固定、輸入輸出明確、AI 可獨立完成 | CI 執行、自動部署 staging、自動產測試覆蓋率報告 |
| **第二層：AI 起草，人審核** | AI 產出初稿，人工確認後使用 | 需求整理、SOW 草稿、PR 描述、Release Note、測試案例 |
| **第三層：必須人工決策** | 涉及商務承諾、品質判斷、架構決策、法律責任 | 接受需求變更、功能優先序、是否上線、客戶驗收簽核 |

---

## AI 不應該做的事情

- 直接承諾報價或範圍給客戶
- 決定 Production 部署時機
- 自動執行 Production 環境任何變更
- 判斷 UAT 「通過」或「不通過」
- 決定 Change Request 是否成立
- 替 PM / QA / 工程師在客戶文件上簽核

---

## Cowork vs Claude Code 定位對照

| 項目 | Cowork | Claude Code |
|---|---|---|
| 主要服務對象 | PM、QA | 工程師 |
| 核心能力 | 整理、起草、比對、提醒 | 開發、測試、文件自動化 |
| 典型任務 | 需求整理、SOW 草稿、測試案例、Release Note | PR 描述、單元測試、API 文件、Bug 修正 |
| 不適合 | 替代 PM 做商務決策、替代 QA 做品質判斷 | 替代工程師做架構決策、直接上 Production |
