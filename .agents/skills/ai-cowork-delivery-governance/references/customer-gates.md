# 客戶 Gate（4 個關鍵簽核點）

## 原則

接案流程中客戶 Gate 只保留 4 個關鍵點，避免因過多簽核節點拖慢開發節奏。每個 Gate 都有明確的「進入前提」、「簽收物」、「後續鎖定的承諾」。

---

## Gate 1：SOW / 報價 / 交期確認

**時機**：開發前，QA 與工程師評估完成後。

### 進入前提（全部完成才能觸發）

- [ ] 需求訪談完成、需求文件初稿確認
- [ ] QA 測試策略確認（測試範圍、高風險功能、工時）
- [ ] 工程師技術評估完成（可行性、工時估算校正）
- [ ] SOW 初稿由 PM 內部審核通過
- [ ] 報價項目已依評估結果調整

### 必要輸入

- SOW（含功能清單、驗收條件、不在範圍項目）
- 報價單（含工時拆分依據）
- 交期計畫（含里程碑節點）

### 簽收物

- 客戶確認 SOW（email / 書面 / 電子簽核）
- 報價確認
- 交期確認

### 後續鎖定

Gate 1 完成後，以下項目**鎖定**：
- 功能範圍（SOW 範圍）
- 報價（含付款條件）
- 主要交期節點

任何變更須走 Gate 2（Change Request）。

### 不應在這裡做的事

- 先讓客戶確認報價，再回頭做技術評估（會導致報價翻車）
- SOW 未包含「不在範圍」清單（客戶誤以為無限範圍）
- 交期沒有里程碑節點，只寫結案日（風險無法管理）

---

## Gate 2：Change Request / 範疇變更確認

**時機**：開發中，QA 驗證後問題分類為「新增需求 / 範疇變更」時。

### 觸發條件（超出原 SOW 範圍的判定準則）

以下任一成立，即屬範疇變更，必須走 Change Request：
- 原 SOW 功能清單未列入的新功能
- 原驗收條件以外的要求
- 系統整合方式改變（API 對接對象、資料格式）
- 架構層級的修改（DB Schema 重構、服務拆分）
- 效能要求提升（新增 SLA）

### 必要輸入

- 原 SOW 對照（原承諾 vs 新需求）
- 影響分析（工時增加、交期影響、技術風險）
- 報價調整方案（或範圍縮減方案）

### 簽收物

- CR 編號與描述
- 客戶簽核（確認新增範圍 + 報價 / 交期調整）

### 後續動作

- 更新 Backlog（加入新任務）
- 調整排程與里程碑
- 必要時修訂 SOW / 報價

### 不應在這裡做的事

- 把新增需求當 Bug 免費修（最常見的接案虧損來源）
- CR 沒有書面確認，只有口頭同意（口頭同意不算）
- PM 自行決定接受 CR 而不評估工時影響

---

## Gate 3：UAT 驗收

**時機**：開發後，版本凍結、UAT 環境部署、QA Smoke Test 全部完成後。

### 進入前提（全部完成才能讓客戶 UAT）

- [ ] 版本已凍結（feature freeze / release tag）
- [ ] UAT 環境已部署（接近 production 設定）
- [ ] 測試資料已準備
- [ ] QA Smoke Test 通過（核心流程可用）

### UAT 驗收範圍

- 依原 SOW 功能清單逐一驗收
- 依需求文件驗收條件確認
- **不接受** UAT 期間提出的新需求（新需求走 CR）

### 客戶回報問題分類

| 問題類型 | 處理方式 |
|---|---|
| Bug（功能未達驗收條件）| 工程師修正 → QA Smoke Test → 重新 UAT |
| 操作問題 | PM 提供操作說明，非保固問題 |
| 新增需求 | 記錄，保固後走 CR |

### 不應在這裡做的事

- 沒做 Smoke Test 就讓客戶 UAT（客戶測到環境問題，浪費時間）
- 沒有凍結版本就 UAT（一邊驗收一邊改功能，結果失真）
- 接受 UAT 期間的新需求並直接修（範疇擴大）

---

## Gate 4：正式簽收 / 上線同意

**時機**：UAT 通過後，正式部署前。

### 進入前提

- [ ] 客戶 UAT 通過（無未解決的 P1/P2 Bug）
- [ ] 所有 UAT Bug 已修正並重新驗收
- [ ] 交付文件草稿完成（Release Note、操作手冊）

### 簽收物

- 正式驗收簽收文件（email / 書面）
- 上線同意（確認上線時間窗口）
- 保固起算日確認

### 後續鎖定

Gate 4 完成後：
- 保固期正式起算
- 後續問題依保固 SLA 處理
- 超出保固範圍的問題另議費用

### 不應在這裡做的事

- 沒有書面簽收就上線（無法確認責任切分點）
- 保固起算日不確認（雙方認知不同）
- 未完成 KT 就結案（客戶不知道怎麼回報問題）
