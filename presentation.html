接案流程的核心痛點

需求模糊

規格不清就進開發，方向錯誤成本極高，開發完才發現做錯方向

資訊落差

PM、QA、工程師各看各的，沒有共同規格基準，驗收爭議多

變更失控

需求邊做邊改，沒有記錄，沒有影響分析，範圍蔓延時程爆炸

尾聲壓力

bug、文件、回歸全部塞到驗收前爆發，品質不穩、交付延期

AI Cowork 的定位

Automation（腳本）

  • 規則固定、輸入輸出明確
  • 不會判斷商業情境
  • 遇例外卡住
  • 適合：跑測試、抓 issue 狀態

Cowork（PM / QA 助理）

  • 根據角色幫忙整理、起草、比對
  • 知道 PM / QA 各需要什麼
  • 有例外可提醒人工確認
  • 適合：摘要、草稿、分類、狀態同步

Claude Code（工程師端）

  • 起草 PR、commit 與 changelog
  • 起草 API / DB Schema
  • 生成 migration / release script
  • 需要工程師 review 與測試

Cowork 與 Claude Code 都是助理；決策、品質與部署責任仍由人承擔。

Claude Code vs Cowork

v3.2 將 AI 介入拆成兩種模式：PM/QA 的 Cowork，以及工程師端的 Claude Code。

模式使用情境典型輸出人工 checkpoint
Automation 規則固定、輸入輸出明確 測試結果、Issue 狀態、Release Note 初稿 例外狀況人工處理
Cowork PM / QA 需要整理、分類、對齊狀態 User Story、測試規劃、回饋分類、Demo 腳本 PM / QA 審核後對客戶或團隊同步
Claude Code 工程師需要起草、檢查、產出技術交付物 PR 摘要、commit、API / DB Schema、migration script 工程師 review、測試、合併與部署

整體接案流程

PM / QA / 工程師 三角色 × 三階段，標示人工 vs AI Cowork 介入點

開發前流程

需求釐清 → 測試規劃 → 技術評估 → 排程

開發中流程

實作 → 持續測試 → 進度協調 → 需求變更管控

開發後流程

完整回歸 → UAT → 上線決策 → 結案

三層 AI Cowork 策略

第一層：可全自動

  • 自動跑測試
  • 自動產進度摘要
  • 自動抓 issue 狀態
  • 自動產 Release Note 草稿

第二層：AI 起草，人審核

  • Cowork：需求整理 / User Story
  • Cowork：QA 測試規劃 / UAT 分流
  • Claude Code：PR 摘要 / commit
  • Claude Code：測試碼 / migration script

第三層：必須人工決策

  • 接受需求變更與否
  • 功能優先序
  • 是否可上線
  • 客戶驗收簽核

第一階段可落地的 AI Cowork 功能

  • PM  會議紀錄 → 需求摘要 — 減少需求整理時間
  • PM  需求 → User Story / 驗收條件 — 快速對齊工程師與 QA
  • QA  需求 → 測試案例初稿 — 減少測試規劃時間
  • QA  PR diff → 回歸測試建議 — 降低漏測風險
  • PM QA  UAT 回饋分類 — 區分 bug / 新需求 / 操作問題
  • PM  Release Note / 交接文件草稿 — 加速交付結案
把固定規則的工作交給腳本，
把整理與起草交給 AI Cowork，
把商務、品質與放行決策留給人。
  • AI 不取代 PM、QA 或工程師
  • AI 協助整理、起草、比對、提醒與報告產出
  • 讓人把時間留給決策、驗證與溝通
